# UXQ 评价维度

UXQ 使用 6 个评价维度（D01-D06）覆盖 UX 评价的核心方面。纯静态采集（无交互动作）时 D02/D05/D06 为 OOS（不适用）。

## 维度定义

| ID | 名称 | 说明 | 静态采集 |
|---|---|---|---|
| D01 | 任务有效性 | 用户能否完成目标任务 | 可测 |
| D02 | 操作效率 | 完成任务所需的时间和步骤 | OOS |
| D03 | 可理解性与认知支持 | 界面信息是否清晰易懂 | 可测 |
| D04 | 可访问性与包容性 | 是否满足不同能力用户的需求 | 可测 |
| D05 | 交互可靠性与错误恢复 | 系统稳定性和错误处理能力 | OOS |
| D06 | 主观体验 | 用户满意度和情感反应 | OOS |

## OOS（Out of Scope）说明

当维度标记为 OOS 时：
- 该维度不参与评分计算
- 报告中必须显式声明该维度未覆盖
- 不能对该维度做出任何结论

## 使用场景

在评价定义文件的 `dimensions` 字段指定要评价的维度：

```json
{
  "dimensions": ["D01", "D03", "D04"]
}
```

建议至少包含 D01（任务有效性）和 D03（可理解性）。

## D03 指标选择（按页面类型）

D03 可理解性的指标必须匹配目标页面的实际功能，不能无差别套用 h1 计数。

| 页面类型 | h1 适用性 | 推荐 D03 指标 |
|---|---|---|
| 内容页面（文档、博客、文章） | 适用 | h1 数量、标题层级完整性、地标区域数 |
| 交互式工具（编辑器、IDE、画布） | 不适用 | title/aria-label 覆盖率、带标签输入框比例、面板区域标识 |
| 仪表盘/数据大屏 | 不适用 | 数据区块标识、图表 aria-label、表格/网格元素数 |
| 表单/流程页 | 部分适用 | 步骤标题、字段标签关联率、错误提示可访问性 |
| 落地页/营销页 | 适用 | h1 数量、标题层级、CTA 按钮可访问名称、导航链接数 |
| 设置/配置页 | 不适用 | 设置分组数、控件标签覆盖率、状态反馈区域数 |

## 通用指标（所有页面类型均应包含）

以下指标不区分页面类型，所有 profile 自动生成时均包含：

| 指标 | 维度 | 说明 |
|---|---|---|
| 跳过导航链接 | D04 | `a[href^="#main"]` 或 `.skip-link`，键盘用户快速跳过重复导航 |
| HTML lang 属性 | D04 | `html[lang]`，屏幕阅读器语言识别的基础 |
| focus-visible 元素数 | D05 | 键盘焦点可见样式，交互可靠性的结构代理 |

**原则**：页面不需要 h1 → 定义中不写 h1 指标和规则。不要把"无 h1"报为缺陷或生成 CONFIRMED_DEFECT。
